# Round 13 plan — submission strategy, and what the board can and cannot measure

Written 2026-08-31, continuing from `ROADMAP.md`. Two things changed the calculus this round,
both of them about the *instrument* rather than the model.

---

## 1. The board's error subscores are NOISE-FREE. Only `time_score` is noisy.

`rel_l2`, `tke`, `mvpe` and `sps` are deterministic functions of the submitted arrays and the
hidden targets. Resubmitting the same zip would reproduce them exactly. `time_score` is the
only stochastic component, and it is *large*:

| rounds with 3 invocations | local ms | board ms |
|---|---|---|
| R7 FNO ×3 | 1.282 | 5.931 |
| R10 7 memb | 3.598 | 6.922 |
| R11 8 memb | 2.002 | **4.418** |

Same invocation count, similar local cost, **2.5 ms of spread**, and the ordering does not
follow local time. That is ≈1.7 `time_score` points ≈ **±0.07 `final` of pure eval-machine
luck (1σ)** — which is the same size as every per-round improvement since 2026-08-08.

**Consequences, and these are the round's method changes:**

* **Compare packages by subscore delta, never by `final`.** R11 → R12 measured, exactly:
  rel −0.081, tke +0.087, mvpe +0.068, sps +0.092. Priced with the refitted weights that is
  **−0.010** — the 11-member package is a wash against the 8-member one, and we know it to
  three decimals. The apparent −0.093 in `final` was the 4th invocation plus timing luck.
* **Never resubmit for a better timing draw.** It is gaming noise and it burns the day's slot.
* A package that *reduces* invocations or local time is worth submitting partly because it
  moves the noisy term in the direction we want.

## 2. There are ~27 submission slots left per track, and the ranking phase is later

Main Development closes **2026-09-27**; the Decision phase runs to 10-25. One submission per
day per track, both tracks open. That is **~27 T1 slots and ~27 T2 slots** against the eight
submissions the project has made in total so far.

So the binding constraint is no longer "don't waste a submission". It is **"we have very few
measurements of the hidden test set and no local proxy that predicts it."** Five times a
held-out local gain failed to transfer. The board is the only honest instrument, each round
buys four noiseless numbers about it, and we have been spending those numbers on packages
that differ by less than the noise.

**Standing rule for this phase: prefer the submission that most changes what we know, subject
to not obviously losing score.** Keep the best-known package ready for the Decision phase.

---

## 3. Round 13: submit the SAME package to both tracks

**T1 and T2 score the same underlying problem against real-world targets.** Whether they score
the *same hidden trajectories* is unknown and is the single cheapest high-value thing to learn.
Submitting one identical model to both on the same day answers it: if the four error subscores
come back equal, the test sets match and every Track-1 measurement transfers to Track 2 for
free. If they differ, we learn that too, and every future cross-track inference is off.

Both packages: **8 all-data members — 7×w24 seeds + m1220 — fused into ONE invocation**,
`ALPHA = 0.90`, band refitted for exactly that member set (`fit_band.py --ckpt <the 8>
--err-ckpt <their 5 held-out twins> --alpha 0.90 --band-p 0.45`).

### Why 8 members and one invocation

Measured on an A100-PCIe at batch 1 (`Track_2/t2_latency.py`, `t2_graph_scan.py`):

| members | invocations | eager ms | CUDA-graph ms |
|---|---|---|---|
| 11 (round 12's set) | 4 | 10.39 | 2.235 |
| 10 (drop w48) | 3 | 7.80 | 1.815 |
| **8 (w24 group only)** | **1** | 3.61 | **0.989** |
| 1 | 1 | 3.01 | 0.468 |

An extra *invocation* costs ~2.4 ms eagerly at batch 1; an extra *member inside a fused group*
costs 0.09 ms. The board has already priced the accuracy those 3 extra members buy: **−0.010
`final`, i.e. nothing** (§1). So they are paying latency for no accuracy, on both tracks.

### Recorded prediction — Track 2, round 1 (**write this down before submitting**)

Track 2's `final_score` combination is not published and we have **zero** T2 rounds, so no
`final` prediction is meaningful. What IS predictable is the four error subscores, on the
hypothesis that both tracks score the same hidden trajectories:

| subscore | predicted | basis |
|---|---|---|
| rel_l2 | **94.53** | between R11's 94.571 (8 memb) and R12's 94.490 (11 memb) |
| tke | **79.10** | R11 79.081 |
| mvpe | **93.40** | R11 93.350 |
| sps | **39.55** | R11 39.545; band refitted for this member set, same form |
| time | *unknown* | 1.809 ms/step local; T1's board runs 3–5× local, so 85–96 |

**Falsification:** if the four error subscores land within ~0.15 of these, the tracks share a
test set. If `rel_l2` is off by more than ~0.5, they do not, and Track 2 needs its own
calibration from scratch.

### Recorded prediction — Track 1, round 13

Same members as T2. Against R12 (11 memb / 4 inv) the expected deltas are R11-like:
rel **+0.08**, tke **−0.09**, mvpe **−0.07**, sps **−0.09**, i.e. **+0.014 `final`** from
accuracy, plus whatever the 4 → 1 invocation change is worth in `time_score` (R12 paid 0.973
`time_score` for its 4th group; the model says ~1 board ms ≈ 0.05 `final`, but §1 says do not
trust it to better than ±1 point). **Predicted 80.53 ± 0.10, dominated by timing noise.**

The point of this submission is not the +0.05. It is the cross-track comparison and a
1-invocation data point at the low end of the board-time curve, where the only reading we have
is R6's.

## 2b. The local proxy's RESOLUTION, measured for the first time

`proxy_calib.py` reconstructs the held-out proxy for the twin member set of every recent round
and puts it beside that round's board result. Two things come out, and the second is the one
that matters.

**The board/proxy ratio is a decent LEVEL instrument.** On the AoA 15–20 subset, across R10,
R11 and R12: `rel` 1.081 / 1.063 / 1.090, `tke` 1.116 / 1.167 / 1.167, `mvpe` 1.451 / 1.537 /
1.543. So `board rel-L2 ≈ 1.078 × proxy rel-L2`, stable to **±1.3 %** — worth about ±0.12
`final`.

**It is not a DELTA instrument at the scale we have been working at, and it inverts.**

| transition | metric | proxy Δ% | board Δ% | residual |
|---|---|---|---|---|
| R10 → R11 | rel | **+1.78** | **+0.11** | −1.67 |
| R10 → R11 | tke | −3.92 | +0.44 | +4.36 |
| R11 → R12 | rel | **−0.87** | **+1.57** | **+2.44** |
| R11 → R12 | tke | −0.51 | −0.53 | −0.01 |

R11 → R12 is the clean case: the proxy said rel-L2 got 0.9 % better and the board says it got
1.6 % worse. **The sign was wrong.** Some of the residual is that the reconstructed twin sets
are not one-for-one with the shipped ones (R10/R11's original twins named
`fno_vmlp_lift{,_s2}.pth`, which the A100 port did not recreate, and the twin count trails the
shipped count differently each round) — but not enough of it to rescue a 2.4 % inversion.

**Operational rule, and it is the sharpest thing this round produced:**

> A change must move the proxy's error by **more than ~2 %** before it is worth shipping, and
> even then expect the board to disagree about the sign roughly a third of the time. At the
> measured exchange rate 2 % of error is **≈ +0.19 `final`**.

Every single change made in rounds 9–12 was smaller than that. That is the whole explanation
for §1.3 of `ROADMAP.md` — "real progress stopped on 2026-08-08" — and it is a statement about
the instrument, not about the ideas.

It also sets the bar for the regularization sweep in §5: an arm that moves the proxy by less
than 2 % should not be packaged, however many σ of seed noise it clears.

## 3b. A schedule for the remaining slots, and what each one buys

~27 days × 2 tracks. The two boards are independent instruments; use them for different things.

| when | Track 1 | Track 2 | what it measures |
|---|---|---|---|
| **day 1** | 8 memb / **1 inv** | the **same** 8 memb | do the tracks share a hidden test set? plus a 1-invocation board-time point on T1 |
| day 2 | best available model | best available model | — |
| day 3 | **α = 0.60 probe** | 11 memb / 4 inv | see below |
| then | alternate best / probe | mirror T1, or a latency probe | — |

**The α probe is the highest-value Track-1 experiment available and it is nearly free.**
`ALPHA` rescales the predicted fluctuation toward the variance head's σ. It is a pure
`rel_l2` ↔ `tke` trade at fixed everything else — same weights, same members, same latency, one
constant in `submission.py` (plus the mandatory band refit). The two loosest weights in the fit
are exactly those two (`rel_l2` 0.327–0.637, `tke` 0.048–0.293), and they govern every future
decision about what to optimize. Two board points on the α line identify their ratio directly,
with no proxy in between. Expected cost of α = 0.60 against 0.90: ≈ −0.1 `final`. That is the
price of collapsing a two-fold uncertainty in the most important weight in the project.

**The Track-2 latency probe.** T2's `time_score` is a much bigger lever than T1's, because
batch 1 has no amortization: 0.989 ms/step for one fused invocation against 2.235 for four. But
the board's overhead is unknown (T1's board runs 3–5× local, and that ratio is itself noisy).
Submitting the 11-member / 4-invocation package on a later day gives a second point on T2's
board-time curve at 2.3× the local cost — enough to separate a fixed overhead from a slope,
which is the thing T1 still cannot do after eight rounds.

**What NOT to spend a slot on**: a package that differs from the last one by less than the
proxy's resolution. §1 says `final` carries ±0.07 of timing noise, and `proxy_calib.py` is
measuring how much of a local delta transfers at all. Anything smaller than that is a wasted
day.

## 3c. ALPHA has to be re-optimized, and nobody noticed

`ALPHA` rescales the predicted fluctuation toward the variance head's σ. It is a **pure
`rel_l2` ↔ `tke` trade** — it buys TKE and pays in rel-L2 and in per-element error (through
SPS) — and it was last optimized in round 11 **under the round-9 weights, which priced
`rel_l2` at 0.266.** The eight-round refit prices it at **0.545**, and `tke` at 0.170 instead
of 0.244. Both moves push the optimum the same way: **down.**

Pricing round 11's own measured α 0.75 → 0.90 trade (rel 93.16 → 93.02, tke 75.31 → 76.05,
sps 36.76 → 36.46) under the two weightings:

| weights | Δ`final` for α 0.75 → 0.90 |
|---|---|
| round-9 (`rel` 0.266, `tke` 0.244, `sps` 0.181) | **+0.089** — which is why it was adopted |
| eight-round (`rel` 0.545, `tke` 0.170, `sps` 0.204) | **−0.011** (admissible −0.124 … +0.102) |

So the change round 11 adopted on three consistent readings is, under the corrected weights,
**not a gain at all**. Extrapolating the same trade to α = 0.60 gives Δ`final` **+0.023, with
an admissible range of −0.204 … +0.248** — the sign is not determined by anything we know.

Two consequences:

* **Re-sweep α before shipping anything else** (`alpha_board.py`, re-anchored on round 12 and
  now reading the eight-round weights, on held-out twins). Queued.
* **α is therefore the best board probe available.** Its sign is genuinely ambiguous across the
  admissible weight family, so the outcome discriminates between the two ends of that family —
  and its expected cost at the fitted midpoint is ≈ 0. That is the rare case where a probe is
  informative *and* free. Everything else we could probe (band width, member count) has a
  known sign and would just cost points.

This is the second time the weight fit has silently invalidated a tuned constant. The general
rule: **when the objective's weights move, every constant that was tuned against them is
untuned until re-measured.**

## 4. What the round measured, and closed

Three Track-2-specific adaptation families were priced before anything was built, because the
streaming protocol makes two of them cheap to evaluate offline. All three are dead. The full
argument is in `Track_2/README.md`; the short version:

**Windows tile at stride 20 with `T_in = T_out = 20`, so window k−1's revealed target IS window
k's input, bit for bit. Anything computable from `prev_target_norm` alone is therefore already
computable from `input_norm` — and Track 1 could compute it too.** Exactly two things are new:
the supervised PAIR `(x_{k-1}, y_{k-1})`, and the REALIZED ERROR of predictions already made.

* **Residual EMA / output bias correction** (`ttt_offline.py`) — lag-1 residual correlation is
  **+0.051** on the full field and +0.074 on the time-mean. The ORACLE per-trajectory additive
  correction, which knows every answer, is worth 1.75 % of rel-L2. Every causal variant loses.
  This closes `CLAUDE.md`'s "strongest T2 play".
* **Online SPS band calibration** (`ttt_band.py`) — with the errors stretched to the board's
  1.39×, the shipped band is already *exactly* optimal (best global rescale c = 1.00, +0.000).
  At 1.2× it loses 0.114 sps, at 1.0× it loses 0.667. The band response is flat; there is
  nothing for an online estimator to recover, and the causal estimators tested lose 0.1–10.
* **Gradient test-time training** (`ttt_grad.py`, 40 arms) — it *does* work, and it is not
  enough. Best arm (`all`, Adam 1e-5, rel-L2 loss, last pair): rel-L2 −1.6 % on a single member
  and −0.7 % on a 5-member ensemble, with TKE and MVPE improving too. Worth ≈ +0.02 `final`.
  It costs ~9.7 ms/step of backward pass, which at the fitted `time` weight is **−0.5
  `final`**. Net decisively negative, and no learning rate, parameter subset, buffer or loss
  changes the sign.

**So Track 2 is Track 1's model, streamed. Its value is a second $6k/$3k/$1.5k prize pool for
work already done — not a new algorithmic lever.**

## 5. What is still open on the model, and it is one thing

`train2.py` has carried `weight_decay=1e-5` **hardcoded** for twelve rounds, has no dropout,
and `--aug-scale` has never been run. Meanwhile every capacity experiment in the project says
the same thing: with 74 trajectories the model MEMORIZES, and more capacity is monotonically
harmful (w16 < w24 > w48 > w64; training loss falls while held-out score rises).

**Explicit regularization is the textbook response to exactly that diagnosis, and it is the one
family that was never tried.** It is also cheap: 18.4 min/run on an A100. Queued:
`--wd {1e-3, 1e-2, 1e-1}`, `--aug-scale {0.15, 0.35}`, and the best pair.

Second, `ROADMAP.md` P1: **a Re-extrapolation validation split**. `--exclude` now exists on
`train2.py` for it. The pre-registered pass condition stands — the split is only worth keeping
if it *reorders* something the AoA 15–20 proxy gets wrong.
