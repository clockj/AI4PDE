## WP1 — Loss and training alignment

**Why.** Architecture tuning is capped at ~2.0 final points and cannot touch TKE, because MSE
training converges to the conditional mean, whose temporal variance is systematically below the
truth. The highest-value change in this package is not an architecture hyper-parameter at all —
it is making the training objective match the metric.

**The key insight.** The metric is `‖p−t‖/‖t‖` computed **per window, then averaged**. Plain MSE
weights every window equally in absolute terms, but low-Re trajectories have small `‖t‖`
(`mean_u = Re·ν/c`, measured `ν/c ≈ 1.1e-5`), so their *relative* error is amplified while
training barely weights them. The hidden test set includes **Re 2968, below the entire training
range** — exactly the regime plain MSE under-weights.

### Steps

| # | change | rationale | cost |
|---|---|---|---|
| 1.1 | per-sample **relative-L2** loss instead of MSE | matches the scored metric; up-weights low-Re windows | 1 line |
| 1.2 | train longer (40 → 120 epochs) | MSE was still falling at epoch 39 (0.0417) | 3× runtime |
| 1.3 | drop the 40 dead input channels (`z` slot) | smaller + faster; invalidates the checkpoint, so fold into a retrain | small |
| 1.4 | denser windows, stride 5 → 2 | ~2.5× training data (12k → 30k windows) | 2.5× runtime |
| 1.5 | width 64 → 96 | only if 1.1–1.4 plateau | 2× runtime |

**Verify:** `rel_l2_score ≥ 96.5` and `final ≥ 84.3` on `val_unseen.npz`, with `time_score ≥ 96`.
Run each change individually against the baseline before stacking — with ±0.1 noise, a stacked
sweep cannot attribute the gain.

**Do not** pursue self-normalization inside WP1. It is worth doing (insurance for Re 2968) but
its benefit is **unmeasurable on either local validation set**, since both sit inside the
training Re range. Keep it as a separate, principled change evaluated only on the leaderboard.

## WP2 — Two-head model: shared latent, separate mean and variance

**Why.** TKE compares `0.5·(var_t(u) + var_t(v))` per pixel over the 20 output frames. It is
**phase-free** — it only measures how much fluctuation sits at each pixel, not whether the eddies
are in the right place. That makes it a far easier target than the field itself.

Measured ceiling: with an **oracle** per-pixel std on top of a *trivial* mean predictor, TKE error
falls to 0.007 (score 99.6) and final reaches **87.39** against a 92.07 oracle. A naive estimator
already gets partway — the input window's own std predicts the target std at corr 0.756.

### Architecture — one trunk, two heads

The heads branch from a **shared decoder feature map**, not from separate networks. This is the
physically correct coupling: turbulent fluctuation intensity is set by the large-scale flow —
shear layers, wake width, separation point — so the variance field must be conditioned on the
same latent that encodes the mean flow. Two independent networks would have to rediscover the
mean flow inside the variance branch from scratch.

```
prev window (B, 40, 32, 64)
        |
  [ shared U-Net encoder ]          inc 64 -> down1 128 -> down2 256 @ 8x16
        |                            the 8x16 bottleneck spans the whole domain:
        |                            this is where the large-scale flow lives
  [ shared decoder + skips ]        up1 128 -> up2 64 @ 32x64  =  F
        |
        +---- head_field   1x1 conv  F -> 40ch   ->  y_hat   (20 frames x [u,v])
        |
        +---- head_logstd  1x1 conv  F -> 2ch    ->  log sigma_hat  (per-pixel, per-channel)
```

Both heads are 1×1 convs on the same `F`, so the split costs ~130 parameters and no measurable
latency. The separation happens in the **latent**, exactly as requested: one representation of
the flow state, two physically distinct readouts from it.

### Composition at output

```python
m      = y_hat.mean(dim=t, keepdim=True)          # 20-frame mean field
f      = y_hat - m                                 # raw predicted fluctuation
f_norm = f / (f.std(dim=t, keepdim=True).detach() + eps)
y_out  = m + f_norm * (alpha * sigma_hat + (1 - alpha) * f.std(dim=t, keepdim=True))
```

The fluctuation is renormalized to carry **exactly** the predicted std. Because TKE only sees
variance, the score is correct when `sigma_hat` is correct — even if the fluctuation field is
blurry and phase-wrong. Note this makes `TKE(y_out) = 0.5·(σ̂_u² + σ̂_v²)` by construction.

**`alpha` is a safety valve.** `alpha = 0` reproduces the current model exactly; `alpha = 1` is
full rescaling. Sweep it post-hoc on validation and keep the best. **This makes WP2 structurally
incapable of regressing the 83.83 baseline** — worst case `alpha = 0` and we have lost nothing.

The `.detach()` on the denominator keeps the unstable `1/std` gradient path out of the graph.

### Loss

```
L = L_field  +  lambda_v * L_var  +  lambda_t * L_tke

L_field = mean_over_samples( ||y_out - y|| / ||y|| )        # the scored metric (WP1)
L_var   = MSE( log sigma_hat, log std_t(y) )                # log space: std spans decades
L_tke   = rel_L2( TKE(y_out), TKE(y) )                      # the scored TKE metric directly
```

`L_var` conditions the head; `L_tke` aligns it with the metric's own geometry. Start
`lambda_v = 1.0`, `lambda_t = 0.5`, then sweep each over {0.25, 0.5, 1, 2} once the pipeline runs.

### Known trade-off

Renormalizing adds uncorrelated fluctuation, which **costs rel-L2**. Measured on the trivial
predictor: 0.134 → 0.166. The trade is strongly favourable — roughly +4 final from TKE against
−0.4 from rel-L2 — and SPS gains too, since it weights a TKE branch at 0.3. But watch rel-L2 and
let the `alpha` sweep arbitrate.

**Verify:**
- Necessary: `tke_score ≥ 85` (error ≤ 0.35) with `rel_l2_score ≥ 95.5` → final ≈ 85.7
- Stretch: `tke_score ≥ 92` → final ≈ 87.0
- Sanity: setting `alpha = 0` must reproduce the WP1 model's score to within ±0.1
- Diagnostic to log every run: `corr(sigma_hat, std_t(y))` and `rel_L2(sigma_hat, std_t(y))`.
  The input window's own std scores 0.756 / 0.559 — **the head must beat that or it is not
  earning its place.**

## WP3 — SPS interval band

**Why.** Cheapest point on the board: **+1.3 final measured** (83.83 → 85.15), zero model change.

The scorer's default band is `±5%·|prediction|`. That scales with local velocity, so where
`v ≈ 0` the band collapses to ~zero width and the target is never inside. A **uniform absolute**
half-width fixes it: on persistence, coverage 0.41 → 0.67 and `sps_score` 55.4 → 59.2. Wider is
not better — `exp(-width/σ)` with frozen `σ = 0.0563870` punishes width exponentially, and
half-width 0.1 scores *below* the default.

### Steps

1. Fit the half-width on `val_seen.npz`, evaluate on `val_unseen.npz`. The `+band` figures in
   the report were fitted and scored on the *same* set, so they are mildly optimistic; this
   split makes the number honest.
2. Return `lower`/`upper` from `predict()`.
3. Then try per-element widths from `sigma_hat` (WP2 gives one for free) instead of a constant.

**Verify:** `sps_score ≥ 59` on `val_unseen.npz` with the band fitted on `val_seen.npz`, all
other subscores bit-identical.

**Hard constraint:** bounds must be finite and satisfy `lower ≤ upper` **everywhere**, or the
scorer zeroes **every** subscore, not just SPS. Assert this before writing `predictions.npz`.

## WP4 — Noise-level estimate (measurement only, no model change)

**Why postponed as a modelling direction.** The scoring target is the *noisy* PIV measurement:
`TKE_target = var_true + var_noise`. A perfect denoiser predicting only `var_true` would
systematically undershoot. Denoising is counterproductive for this metric, and a variance head
trained on real targets learns the sum automatically — which is what is scored.

**Why measure it anyway.** The noise fraction sets expectations for WP2's ceiling and tells us
whether the noise variance is a large enough component to deserve explicit treatment later.

### Method

- **Temporal:** true turbulence is temporally correlated, PIV noise is white, so
  `var_noise ≈ var_t(u) − autocov(u, lag 1)` per pixel.
- **Spatial cross-check:** high-wavenumber tail of the 2D spatial spectrum.
- **Sim reference:** `train_sim` has no measurement noise. In self-normalized units its
  turbulence intensity matched real within ±40%, giving an independent bound on the `var_true`
  fraction.

**Deliverable:** noise fraction per (Re, AoA), written into the next report. No score target.
Decision rule: if noise is **< 10%** of total variance, ignore it permanently; if **> 30%**,
reopen explicit noise modelling after WP2.

## Explicitly out of scope

- **Diffusion / generative models.** Settled negative result: PDE-Refiner 82.53 vs its MSE
  control 83.83, worse on TKE at 4× the cost. Full ACDM fails on arithmetic alone (tens of steps
  × 20 frames ⇒ `time_score` ≈ 26). One caveat recorded for the future: PDE-Refiner's final step
  uses `σ_K = 1e-3`, so it never actually *samples* — a true conditional sampler would have the
  right variance by construction. Revisit only if WP2 plateaus.
- **Sim pretraining for the fluctuation field.** Sim's std field predicts real targets *worse*
  than the real input window's own std (0.628 vs 0.559), it lacks the measurement noise the
  metric scores, and sim/real are not phase-paired — statistics can be aligned, instantaneous
  fields cannot. (Sim pretraining of the *trunk* on this backbone remains untested and is a
  separate question.)
- **Further speed work.** At 0.87 ms the U-Net has ~0.5 points of `time_score` left.
- **CNO, Transolver, DeepONet.** All dominated.
